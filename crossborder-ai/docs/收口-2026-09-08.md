## 二、修复的问题（按根因分三类）

### 1. 核心 bug —— content.py settings 遮蔽

`generate_listing` 函数内 `from app.core.config import settings` 把 settings 变成**函数局部变量**，
遮蔽模块顶部同名的 settings。`generate_image=False`（默认分支）不执行该 import，函数末尾读
settings 时触发 `UnboundLocalError: cannot access local variable 'settings'`。
只有走附图分支才会误执行 import，所以常规路径必崩、附图路径反而不崩——很隐蔽。

修复：删除函数内 import，统一用模块级 settings。附图调度失败从 `except: pass` 改为记
`logger.warning`。

### 2. 安全 HIGH —— 9 处 IDOR 跨租户读写

补 `user_id == current_user.id` 归属过滤（他人资源一律按 404 处理）：

- images `/status/{task_id}`：加鉴权 + 归属（此前**未鉴权可读任意任务**）
- products：list / get / delete / batch-delete（get 同时去掉 `@cache`——原按 URL 键缓存跨用户串数据）
- content：generate_listing / a-plus 的商品 fetch
- shopify：push 的商品 fetch

配套：图片生成失败**错误信息脱敏**——供应商原始报错只进服务端日志，落库/回显一律中文通用文案。

### 3. 测试基建 —— conftest 共享库引发 409 连环

原 test_engine 是 **session 级共享** SQLite，而 auth_token 用固定邮箱 test@example.com 注册。
一旦有测试触发了会显式 commit 的端点（新增 images/persona/compliance 路由），同会话里 pending
的注册用户被一起落库 → 之后所有测试的 auth_token 撞 409（全量回归 21 error）。

修复：test_engine 改 **function 级 + StaticPool**，每条测试独立内存库，天然隔离。
scheduler_lock 断言对齐当前 job（订阅过期任务已随 Subscription 模型移除）。
