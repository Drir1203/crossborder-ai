# VeyaShip 产品诊断报告：主题 · 功能 · AI 画像

> **视角**：跨境卖家痛点 × 商业化 × 资深前端/架构/UI
> **日期**：2026-09-03　**方法**：全仓只读勘探（前端 / 后端 / 测试 13 个路由 + 17 个页面文件）+ 9 套 i18n 抽查 + 竞品基准
> **结论形式**：诊断分级（🔴阻断 / 🟠高 / 🟡中 / ⚪低）+ 路线图 + **SDD 规格化改进方案（待确认）**

---

## 0. TL;DR（先看这段）

**总判断**：VeyaShip 现在的完成度，是一个"**视觉有品牌感、后端有骨架、Agent 是真差异点**"，但 **多语言是半成品、F7/F8 名不副实、商业化未闭环、AI 画像割裂** 的高完成度 Demo。

一句话定位问题——**产品想同时做太多事，导致没有一条从"注册 → 第一次成功产出 → 发布到店 → 付费续费"被完整焊死**。代码量不缺，缺的是四个环节的咬合：

| 环节 | 现状 | 卡点 |
|---|---|---|
| **激活** | 新用户登录即空 Dashboard | 抓 1688 第一步就需要 Onebound Key，**却没有配置入口**；零引导 |
| **价值** | Listing / 出图质量在线 | 品牌调性只注入标题；普通生成不跑合规；发布到 Shopify **OAuth 三处 bug 直接断死** |
| **信任** | 视觉精致 | 自动退款是广告词点不到；竞品/净利做了却藏在入口外；favicon 还是 Vite 默认 |
| **付费** | 套餐对比页 + 人工审核升级 | 无真实支付接线、积分口径造假、白名单接口**任意用户可越权放行**、升级一次发≈10万积分存成本敞口 |

**三个核心建议**：
1. **别再堆新功能**——当前 80% 的商业价值藏在"把已有卖点焊死、把闭环跑通"里。F8 发布断死、抓取第一步断、退款无入口，任何一个都是"看起来是产品、实际上做不到"的信任负资产。
2. **AI 画像必须收成一个人**——现在的平台里有"中文决策顾问"和"英文 copywriter"两个互不相识的人格，品牌调性断层注入。卖家付钱买的是"**懂 1688、懂 Amazon/Shopify、懂中国卖家、不敢乱来（合规）**"的代运营副驾，不是一组按钮。
3. **先做战略选择题再动手**——多语言是这次体检里最深的分歧点：9 套 UI 语言文件形同虚设，同时宣称 11 平台 / 17 生成语言。**产品还没决定自己是"中国卖家的中文工具"还是"全球 SaaS"**。这个决定影响上面所有优先级，本文 §2.3 单独分析。

## 1. 用户是谁，他们为什么掏钱

### 1.1 目标画像（来自记忆 + 代码默认值交叉确认）

- 中国跨境卖家，**非技术**，不开 .env、不配 API Key、不想读文档。
- 货源锚定 **1688**，成交锚定 **Amazon US**（Agent 选品 prompt 硬编码 "Amazon US 市场"，成本/价格全 ¥）→ 判断：**默认用户 = "从 1688 拿货、卖到美国" 的中小卖家**，多平台（eBay/Shopify/TikTok/SHEIN/Temu…）是宣称而非真实深度。

### 1.2 这类卖家的五类真痛点

| # | 痛点 | 对产品的含义 |
|---|---|---|
| S1 | **上新慢**：采集-改图-写文案-改格式-发布，逐平台重复 | 要卖"整条流程 + 一键/一条指令做完"，不是单点工具 |
| S2 | **怕合规翻车**：违禁词、侵权词、极限词、平台字段/字符规则；被下架损失远大于工具费 | 合规**必须内生且闭环**，这是能撑起溢价的信任点 |
| S3 | **怕 AI 幻觉**：虚构参数、瞎翻译（度量衡/币种/俚语）直接导致退货 | 需要"来源可核对 + 后置校验 + 站点规则约束" |
| S4 | **怕被平台判重复**：模板批量生成 → 同质化降权 | 需要差异化多版本、每个 SKU 独立生成 |
| S5 | **不会做图/不会选品算账**：无设计能力、Excel 算净利头大 | Agent 用自然语言把"算利润/选品/起标题"讲清楚 = 最顺手的价值展示 |

### 1.3 竞品基准（2026 实测价格带）

| 产品 | 定位 | 价格带 | 给 VeyaShip 的启示 |
|---|---|---|---|
| [VibeListing](https://apps.shopify.com/vibe-listing?locale=zh-TW)（Shopify 应用） | AI 图 + SEO listing + SEO 审计 + Copilot 工作流 | 免费30次/月 → $29 → $149 | 免费给"可感知的少量成功"，再卡量 |
| [eComAI](https://apps.shopify.com/ecomai-product-page-builder) | URL/CSV 批量生成完整商品页（含 meta/FAQ/alt） | $10/$50/$250 | **CSV/URL 批量 + 一次生成整页**是刚需形态 |
| [ListingAI](https://www.producthunt.com/products/listingai-5) | Amazon/Shopify/eBay SEO listing + 平台差异化 + 长尾关键词 | 免费3条/天 → $19 | 平台差异规则（Amazon 75 字符压缩预览）做得很细 |
| [ProductPolish](https://www.capterra.com/p/10041995/ProductPolish/) | 文案+图+8平台集成一键发布 + 品牌包 + 审核流 | 免费 → €29 → €199 | 多平台发布 + 品牌一致性是 Pro 档卖点 |
| [ListingRVA AI](https://www.capterra.com/p/10042127/ListingRVA-AI/) | 单张图出 12 风格图 + SEO 文案 + 团队审核流 | 免费 → $29/$79/$199 | **一张产品图 → 全套交付物**的"交付感" |
| [Catalister](https://toolchase.com/tool/catalister/) | 多平台 + 产品研究 + 竞品监控 + 白标 | €14.99 起，按量积分 | 竞品/看板要**有洞察**（有存、有对比、有结论）才值得单列 |
| 店小秘（[ERP 内嵌 AI](https://www.sohu.com/a/884847890_122004159)） | 采集→AI→翻译→刊登全链路，接入 DeepSeek/豆包 | 免费版强 | 对手是"免费+量级"，VeyaShip 必须靠 **Agent 决策 + 合规深度** 错位，不能拼铺货工具广度 |

**共性结论**：
- 竞品免费层都在 **$0 且给 30 次/月左右**，用"可见成功"激活——VeyaShip 免费 30 积分方向对，但**这 30 次必须先能成功**（第一步 1688 就断 = 免费也救不回来）。
- 付费档按**量/包月订阅**，核心卖点在 **SEO 深度 + 平台规则差异 + 品牌一致性 + 一键发布**。
- **合规/风控是明确的加价点**（店小秘宣传上架通过率 99.4%、内置违禁词/专利筛查），不是成本项。

## 1.4 护城河体检（诚实版）：优势 / 幻觉 / 可激活的壁垒

> **先说结论**：今天 VeyaShip 没有可称"护城河"的壁垒，但有 **4 个差异化种子**——方向选对了、骨架已在代码里，只是都还断/薄/没喂数据。护城河 = 闭环焊死后产生的**数据沉淀 + 店铺绑定 + 信任深度**，是接下来 2–3 周闭环工作的产出物，不是规划出来就能写下来的。

### 1.4.1 先拆幻觉：这些"优势"不是护城河

| 自认为的优势 | 真相 | 复刻成本 |
|---|---|---|
| 接入 DeepSeek / 通义万相 / Replicate | 大模型人人可调，一键可换 | 零（几天） |
| 11 平台 × 17 语言下拉 | 只有列表没深度（字段/字符/本地化全空），店小秘 70+ 平台 | 数周 |
| "AI 生成 Listing / 出图" | ListingAI $19、VibeListing 免费 30 次，SEO/图片深度都比现态强 | 数周 |
| 积分 + 套餐 SaaS 外壳 | 行业标配，且现态有成本敞口（≈10万积分）与白名单越权洞 | 数周 |
| "我们是 AI 公司 / Agent 技术" | AI wrapper 本身不构成壁垒，人设可被仿 | 数月 |

### 1.4.2 四个差异化种子（代码里**真有**，需被激活）

| 种子 | 代码证据 | 现状 | 长成什么护城河 | 激活条件 |
|---|---|---|---|---|
| ① **Agent 自然语言编排** | ReAct + Function Calling + SSE 实时流 + scheduler 任务锁，全仓测试最扎实（~30 用例） | ✅ 已跑通 | 竞品几乎全是表单工具；"说一句『蓝牙耳机能不能做』→ 自动选品→算利润→写 Listing"的**副驾形态**是真差异 | 本身不持久（形态可仿），价值在当载体喂给 ②③④ |
| ② **集成 + 数据在手（ERP 型绑定）** | Shopify OAuth/发布/退款/订单、1688 直抓雏形都在，只是断链 | ⚠️ 断 | 店铺授权 + 商品/图片/Listing 沉淀在平台 = **切换成本**。店小秘的护城河本质不是 AI，是"数据在我这，你走不了" | P0-1 OAuth 焊死、P0-2 抓取入口、图结果落库 |
| ③ **垂直 know-how：合规 × 类目 × 平台规则库** | 后端 Agent 有 compliance_check/fix；前端 `PLATFORM_BANNED_RULES`（死代码未接线）；persona `banned_words` | ⚠️ 埋了半套 | 收拢成**按平台×类目的合规/关键词知识库**并随真实使用累积 → 通用 AI 没有、表单竞品不深做，**唯一"越用越强"的资产** | CAP-05 接线 + 后置校验闭环 + 存储每次合规命中/修正 |
| ④ **信任型自动化（让 AI 动钱）** | 自动退款后端真调 Shopify Refund API，无护栏无审计 | ⚠️ 有芯无壳 | "**带护栏的自主运营**"：自动上架/退款/合规拦截、全部留痕可审计。不可替代性来自"敢 + 可靠"，不是"能生成" | CAP-02/03 护栏 + 审计日志 + UI |

### 1.4.3 复刻难度矩阵（这条壁垒别人多久能抄）

| 资产 | 竞品抄它的难度 | 为什么 |
|---|---|---|
| 大模型接入 / 单点生成 | 低（周级） | 不构成壁垒，已排除 |
| Agent 对话形态 | 中（月级） | 形态可仿，但"流程真的可靠到敢托管"难仿 |
| 集成 + 店铺绑定 + 数据沉淀 | 中高（季级） | 要过 Shopify 审核、要积累渠道关系，且迁移成本在卖家侧累积 |
| 合规×类目规则库 + 累积命中数据 | 高（持续+数据门槛） | 需要真实下架/拦截事件反哺，纯抄只能抄到静态表，抄不到分布 |
| 敢动钱的自动化 + 信任 | 高（信任门槛） | 一次事故就归零，需要护栏+审计+赔付预期背书 |

### 1.4.4 为什么"焊死闭环"就是建护城河的起点

上面 ②③④ 的共同前提是同一个：**真的有人在用，并在平台里产生数据**。而现在这条链是断的——抓不到货 → 无商品数据；发布断死 → 无店铺绑定；Radar 不存储、图片结果存内存、Analytics 孤儿 → **数据根本没在沉淀**。一个没人在日常依赖的工具，谈不上锁定，也谈不上数据飞轮。

> 因此本报告把 P0-B（OAuth/抓取/退款闭环）、P0-C（合规+品牌一致）排在"新功能"之前，不是因为求稳，而是因为**那是唯一通向护城河的路：先被依赖，才有护城河**。短期能让你在市场上站住的不是单项功能，而是"Agent 副驾 + 集成深度 + 垂直规则库"三件事方向对了且骨架已在；长期的分野在于闭环之后敢不敢把 ②③④ 的数据与信任养起来。

### 1.4.5 本期定位与立项（2026-09-03 已对齐）

> **主打定位**：对话驱动的 AI 运营副驾——卖家既能**问**它"蓝牙耳机能不能做"拿市场/利润建议，也能**把 1688 链接交给它**跑完 抓取 → 合规文案 →（绑店后）发布/退款 → 复盘；"问"与"做"同在一个对话框，产品默认中文壳（面向中国卖家、内容输出多语种）。

> **本期立项（已勾选）**：端到端闭环主线 CAP-01/02/03 + AI 人设与合规闭环 CAP-04/05 + 激活与数据留存 CAP-07/图结果落库（白名单越权洞顺手堵）；**计费配额 CAP-08 延后**一期。后续按 SDD：每条能力点先出成文 Spec（Requirement + Given/When/Then + 验收）→ 用户确认 → RED→GREEN→IMPROVE。

| T8 | 营销信任素材 | Landing + 套餐对比 + 管理员审核页齐备 | 缺"案例/前后对比/合规能力证明/数据安全承诺" | 注册转化与付费说服力弱 | 🟠 |

### 2.2 做得对、必须保留的（别改）

- **视觉定制是加分项**：琥珀金玻璃拟态 + aurora 光晕 + 颗粒噪点 + 16px 大圆角 + 渐变主按钮，远超"通用后台模板"，是差异化资产。五套主题（dark 默认/ocean/warm/forest）的换肤机制也完整。
- 空状态普遍做了"图标+文案"（Products/Radar/Images/Batch），是规范——**下一步把它们升级成"行动引导"**即可。
- 统一 Sidebar+Header 壳、ErrorBoundary、响应式布局基础都在，工程底子健康。

### 2.3 战略分歧点：先定"产品是给谁说话的"

多语言体检暴露的不只是代码问题，是**产品战略没拍板**：

- 若面向**中国卖家**（当前默认，¥计价、中文文案、1688 货源）→ 正确姿势是 **UI 收敛为中文优先**，把 9 套 UI 语言改为"后续出海再开"，把精力放在**生成内容的 17 种目标语言质量**上（那才是卖家真正花钱的地方）。
- 若面向**全球卖家** → 则 i18n 是 P0，要从"硬编码中文重构为全量 `t()`"，工作量以周计且要持续维护，当前团队显然没这个余力。

> **建议**：拍板为**第一种**（中国卖家做全球生意），即"**中文产品壳 + 多语种内容内核**"。这能让 T1 从"半成品负担"变成"一句话可解释的产品边界"，并把多语言投入导向**卖家的目标市场内容**（合规、本地化、SEO 词），而不是自己的导航栏。
> 若你已另有判断（例如产品确实要全球发），请在确认规格前指出——它会改写 §7 里 CAP-06。

### 3.2 🔴 P0 断点明细（按对商业伤害排序）

**P0-1　Shopify OAuth 断死 → F8 发布、F7 退款全线不可达**
- 前端把 `shop=${shop}.myshopify.com` 传给后端，后端又拼一次 `https://{shop}.myshopify.com` → `xxx.myshopify.com.myshopify.com`（[ShopifyPage.tsx:74](frontend/src/pages/shopify/ShopifyPage.tsx) ↔ [shopify.py:145-146](backend/app/routers/shopify.py)）。
- 前端 `window.open` 打 `/auth` 端点，但端点返回 **JSON 不是 302** → 新窗口打印一段 JSON（[shopify.py:151](backend/app/routers/shopify.py)）。
- callback 依赖 `Depends(get_current_user)` 收 JWT，而 Shopify 浏览器重定向**不带 Authorization 头** → 永远 401，永远拿不到 channel（[shopify.py:158](backend/app/routers/shopify.py)）。
- 后果：/push 的合规+建商品逻辑再完整也跑不通；"自动退款后端是真的但 UI 点不到"。**F8/F7 在落地页和套餐文案里是卖点，实际是断链**——这是最伤信任的一处。

**P0-2　第一价值时刻断：1688 抓取要 Onebound Key，但全产品无配置入口**
- 后端有真实抓取 + 直抓降级（[scraper.py:155-200](backend/app/services/scraper.py)），`/settings/scraping` 接口也在，但 **SettingsPage 只有"品牌调性"一个 Tab**，Key 只能靠 .env 或裸打 API。
- 卖家视角：注册→拿到 30 积分→想抓第一个品→抓不到，也不知道去哪配。**免费额度第一步就失败 = 激活失败**。而且设置 API 是无鉴权语义（见 P0-4），绝不能让卖家自己配。

**P0-3　积分与计费是"假闭环"**
- `used = 100 - credits` 硬编码口径，免费用户只有 30 积分，used 一开始就是假的（[analytics.py:83](backend/app/routers/analytics.py)）。
- 人工审核通过后一次性发放**≈10万积分**，而每次调用扣 1 → 单价 ¥99/¥249 换海量 AI 调用，**边际成本敞口**无计量、无配额、无告警。
- 决策：**短期**保留"人工转账+管理员审核"（对中国卖家用微信/支付宝转账反而真实），但必须改成——审核通过 = **解锁套餐配额（例如每档每月 X 次）+ 按套餐结算积分包**，而不是无限积分；**中长期**接真实订阅网关（可复用 Creem 或换 Stripe，见 ⚪P2-4）。

**P0-4　前置权限漏洞：付费墙可以被白名单接口绕过**
- 白名单增删改只 `get_current_user`、不校验 `require_admin`（[settings.py:27-53](backend/app/routers/settings.py)）→ 任何登录用户可把自己加进 `WHITELIST_EMAILS`（内存集合，重启前持续生效）绕过套餐 gating；scraping Key 写接口同理（[settings.py:84-107](backend/app/routers/settings.py)）。
- 这是**收入与安全双重风险**，改 3 行代码即可堵住，优先级最高。

**P0-5　普通 Listing 生成不走合规闭环**
- 合规检查/修正只存在于 Agent 主动调用（[agent_orchestrator.py:1045-1097](backend/app/services/ai/agent_orchestrator.py)）；用户从商品页直接点"AI 生成 Listing"（/content/generate）**不做任何违禁词后置校验**；前端精心实现的 `PLATFORM_BANNED_RULES` 违禁词表是死代码不生效。
- 卖家最贵的信任点（S2 怕违规下架）恰恰在主流路径上没防护。见 §4/CAP-05。

### 3.3 🟠 P1 断点/缺口

- **P1-1 竞品 Radar 名不副实**：前端做了"多链接批量对比+价格区间图"，后端只有单条抓取、无存储、无 AI 分析，本质是"抓 N 个商品摆一起"；且**无导航入口**。

- **P1-6 品牌调性注入断层**（详见 §4）：用户填了品牌调性，但只有标题用到。

## 4. AI 画像体检

### 4.1 核心问题：平台里住着两个互不相识的"AI"

| 场景 | 画像 | 证据 |
|---|---|---|
| Agent 对话 / Dashboard | 中文「跨境电商 AI 决策助手」顾问口吻 | [AgentPage.tsx:113](frontend/src/pages/agent/AgentPage.tsx)：`你好！我是你的跨境电商 AI 决策助手…说"蓝牙耳机能不能做"→AI 分析品类` |
| 文案 / SEO / 出图 | 英文 `professional copywriter / SEO specialist`，工具腔 | [deepseek.py:223-334](backend/app/services/ai/deepseek.py)：`You are an expert cross-border e-commerce copywriter…` |
| 错误提示 | 生硬且中英混杂（「AI 生成服务暂不可用，请稍后重试」/「生成失败」） | [content.py:233](backend/app/routers/content.py) 等 |

用户感觉是"一个能聊天的顾问 + 一组冷冰冰的工具"，语气随页面跳变。**对卖家而言，AI 是"人"还是"按钮"直接决定付费意愿与是否敢把活交给它。**

### 4.2 Persona 注入断层：填了不等于生效

用户设置的品牌调性（Persona）链路**只在标题生效**：

| 生成类型 | 是否注入 Persona | 证据 |
|---|---|---|
| 标题 `_generate_title` | ✅ 注入 | [content.py:366](backend/app/routers/content.py) `brand_context` |
| 描述 `_generate_description` | ❌ 收了参数但**完全忽略** | [content.py:389-401](backend/app/routers/content.py) |
| 卖点 `_generate_bullets` | ❌ 忽略 | [content.py:404-416](backend/app/routers/content.py) |
| SEO `_optimize_seo` | ❌ **无此参数** | [content.py:419-430](backend/app/routers/content.py) |
| 专家模式 Agent | ❌ 只传 tone 字符串，persona 丢弃 | [agent.py:212-221](backend/app/services/ai/agent.py) |
| Agent 助手生成 Listing | ❌ 不加载 persona | [agent_orchestrator.py:688-728](backend/app/services/ai/agent_orchestrator.py) |
| 独立图片路由 | ✅ tone+brand_name | [images.py:104-114](backend/app/routers/images.py) |
| content 内嵌出图 / 专家出图 | ❌ 固定 prompt 白底 | [replicate.py:40-45](backend/app/services/ai/replicate.py) |

**额外发现**：前端精心实现的一套 persona 注入 + 平台违禁词规则（[prompt-builder.ts](frontend/src/lib/ai/prompt-builder.ts) / [image-prompt-builder.ts](frontend/src/lib/ai/image-prompt-builder.ts)）**全仓库无人 import = 纯死代码**。等于"合规规则写过、没接线；品牌调性要穿、只穿了标题"。

### 4.3 Persona 字段本身也不够（要升级成 Brand Kit）

现在表单只有：`brand_name / tagline / description / tone(7选) / banned_words`（[SettingsPage.tsx:39-128](frontend/src/pages/settings/SettingsPage.tsx)）。缺对卖家最关键的三样：
- **目标市场/目标平台**（美国 Amazon? 欧洲 eBay? TikTok 东南亚?）——决定语言、度量衡、币种、合规差异；
- **产品类目/核心卖点**（美妆 vs 3C vs 母婴，合规红线完全不同）；
- **视觉/图片风格偏好**（现在图片只有 tone 字面量，无法影响构图风格）。

### 4.4 内容质量与合规的真实差距

| 能力 | 现状 | 风险/价值 |
|---|---|---|
| 平台字段差异 | 一句 `Format for {platform} requirements` 带过；标题统一 200 字符 | Amazon 标题上限与 eBay/Shopify 规则不同，硬编码=各平台都会错 |
| SEO 关键词 | 靠 LLM 自发，"Front-load keywords"，无关键词库/竞品词注入 | 卖点（卖家精灵/Describely 的护城河）缺失 |
| 本地化 | 无；仅死代码 translate_content 提过"cultural adaptation"，无路由 | 度量衡/币种/俚语错误 = 退货，S3 痛点未解 |
| 币种 | UI 全 ¥ 硬编码 | 卖给美国市场却在卖家端展示没问题，但若导出含 ¥ 内容则翻车 |
| 合规后置校验 | 只 Agent 主动做；普通生成裸奔 | S2 信任点缺口（见 P0-5） |

### 4.5 建议的 AI 画像（一句话）

> **「一个懂 1688、懂你目标市场平台、说中国卖家语言、永远先把合规红线摆在创意前面、每个产出都可回到你的品牌」的店铺运营副驾」**

落地要点（进 CAP-04/CAP-05）：
1. 全站统一 **一位有名字/固定 system persona 的助手**，中文对卖家说话、英文对买家平台内容做事，语气一致。
2. 把 Brand Kit（§4.3）做成**后端全局上下文**，注入到 标题/描述/卖点/SEO/图/专家模式/Agent 所有出口 + **后置校验**（读回生成内容检查 banned_words 与平台违禁词）。
3. 文案结果提供"已注入的品牌项 / 违规已拦截项"让卖家**看得见 AI 干了什么**（建立信任、可核对）。

## 5. 商业化漏斗与路径

以"注册 → 付费"四段看当前卡点与动作：

| 漏斗段 | 当前断点 | 建议动作 | 对应 |
|---|---|---|---|
| ① 激活 | 空 Dashboard、第一步抓取断、无引导 | Onebound 配置入口（管理员侧）+ 抓取向导 + 新用户 3 步 onboarding | P0-2、T6、CAP-01/07 |
| ② 第一次成功产出 | 生成可用但 persona 断层、合规裸奔 → 质量参差 | Brand Kit 全链路注入 + 合规闭环 | CAP-04/05 |

**单位经济学提醒**（容易被忽略的坑）：积分 = AI 边际成本。现设计"包月解锁 + 每调用扣 1 + 审核发≈10万"在极端使用下**成本无上限**。建议改为 **套餐配额（标准档月 X 次生成/Y 积分）+ 超量按积分包购买**，并把 1 次图片生成与 1 次文案的积分成本**分档**（图贵文廉），否则图片功能会被滥用打穿毛利。
