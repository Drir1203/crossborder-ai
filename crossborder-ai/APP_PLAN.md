# VeyaShip 移动端（App / 小程序）同步方案

> 更新时间：2026-08-04
> 结论：**高度可行**，后端已是 API-first，且已有微信小程序底座

---

## 一、可行性结论

| 有利条件 | 说明 |
|---------|------|
| 后端已是 API-first | FastAPI + JWT + REST（`/api/v1`），天然服务多端，基本不用改 |
| 已有小程序底座 | v2/v3 已覆盖 6 个轻量功能，可直接扩展 |
| 已有微信登录 | `/api/v1/auth/wx-login` 已实现 |
| 技术栈兼容 | React + TS 与多端框架（Expo / Taro / uni-app）兼容 |

## 二、App 形态选择

| 方案 | 说明 | 适合 |
|------|------|------|
| **A. 扩展现有微信小程序**（主力） | 中国卖家都在微信里，触达最好，已有底座 | 国内卖家为主 |
| **B. 原生 App（Expo/RN）** | iOS/Android 商店 + 强推送 | 海外卖家 / 需要强推送 |
| **C. PWA 包壳** | 成本最低，复用全部 React 代码，可安装 | 快速全功能覆盖 |

**推荐**：小程序扩展为主 + PWA 可选。

## 三、功能同步清单

### ✅ 适合 + 后端已就绪（高价值）

| 优先级 | 功能 | 移动端优势 | 现状 |
|--------|------|-----------|------|
| P0 | 品类分析 / 利润计算 / AI 助手 / 合规 / 订单 / 首页看板 | 碎片时间随手用 | 小程序已有 |
| **P1** | **整店巡检结果 + 推送通知** | 每天自动巡检完**主动推给你**"你的店铺有 N 个商品需处理" | 后端接口已就绪，只差小程序页面 + 订阅消息 |
| **P1** | 商品列表 / 巡检历史查看 | 随时看店铺健康 | 后端已就绪 |

### ⚠️ 适合但需少量后端配合

| 功能 | 说明 |
|------|------|
| 选品决策 | 聊天式驱动（AI 助手内做），交互简化 |
| 定时提醒订阅 | 小程序订阅消息，需记录用户订阅状态 |

### ❌ 不适合同步（保留 Web）

| 功能 | 原因 |
|------|------|
| 1688 抓取 / Listing 编辑 | URL 输入 + 长文编辑，Web 体验好 |
| Shopify OAuth 授权 / 发布 | 复杂授权流程 |
| 批量 CSV 导入 | 文件操作 |
| AI 图片生成 | 重资源 + 大图预览 |
| 设置 / API 配置 | 管理员功能 |

## 四、架构方案

```
微信小程序 / PWA / RN App
        │ HTTPS
        ▼
   现有 FastAPI 后端（/api/v1，无需大改）
        │
        ▼
 PostgreSQL + AI 服务（DeepSeek / Replicate）
```

**移动端专属新增能力**（少量后端工作）：
1. **巡检推送**：`POST /api/v1/push/subscribe`（记录订阅）+ scheduler 巡检完后推送
2. **小程序登录**：已有 `/auth/wx-login`
3. 其余接口直接复用

## 五、实施阶段

| 阶段 | 内容 | 工作量 |
|------|------|--------|
| 1（已有） | 小程序 v2/v3 P0 功能 | 已完成 |
| **2（当前）** | 小程序加「整店巡检」页 + 巡检推送订阅 | ~2-3 天 |
| 3（可选） | PWA 包壳全功能 | ~2 天 |
| 4（可选） | RN 原生 App | 2-4 周 |
