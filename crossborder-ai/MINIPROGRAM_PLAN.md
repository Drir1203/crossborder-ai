# 微信小程序开发计划

> VeyaShip AI 小程序端
> 基于现有 API，快速开发

---

## 一、适合小程序的 core 功能

小程序的特点是：**轻量、碎片化、高频**。不适合做重操作（生成长文本、批量上传）。

| 优先级 | 功能 | 适合原因 |
|--------|------|---------|
| **P0** | **AI 品类分析** | 输入品类名 → 看报告，轻量高频，适合碎片时间 |
| **P0** | **利润计算器** | 输入简单，出结果快，选品时随手用 |
| **P1** | **AI 助手对话** | 聊天界面，小程序原生支持好 |
| **P1** | **Dashboard 看板** | 看关键数据（商品数、分析次数、积分） |
| **P2** | **合规检查** | 输入文本 → 出结果，轻量 |
| **P2** | **Shopify 订单** | 查看最近订单状态 |
| **P3** | **商品管理** | 查看商品列表（不做编辑） |

### 不建议做

- AI 生成 Listing（流程太长）
- CSV 批量导入（文件操作）
- Shopify 发布（多步操作）
- A+ 内容生成（重操作）

---

## 二、技术方案

### 架构

```
微信小程序（前端）
    ↕ HTTPS
现有 VeyaShip 后端 API（不变）
    ↕
PostgreSQL
```

**不需要额外后端**——现有 API 完全够用。

### 技术栈

| 层 | 技术 |
|----|------|
| 框架 | 原生微信小程序 / uni-app |
| 请求 | wx.request |
| 状态 | 本地 storage |
| UI | WeUI / 自定义 |

### 微信登录对接

```
小程序登录 → wx.login() → 获取 code
→ 调后端 /api/v1/auth/wx-login → 返回 JWT token
→ 后续请求带 token 调用已有 API
```

后端需要新增一个微信登录接口。

## 三、开发工作量估算

| 功能 | 估时 | 说明 |
|------|------|------|
| 项目初始化 + 微信登录 | 1 天 | 框架搭建、登录流程 |
| 品类分析页 | 1 天 | 输入框 + 报告展示 |
| 利润计算器 | 0.5 天 | 表单 + 结果 |
| Dashboard 看板 | 0.5 天 | 数据卡片 |
| AI 助手对话 | 1 天 | 聊天界面 + 对话历史 |
| 合规检查 | 0.5 天 | 输入文本 → 结果 |
| 总工时 | **~4.5 天** | |

---

## 四、建议分期

```
第一期（MVP，2 天）：
  品类分析 + 利润计算器 + 微信登录
  → 先验证小程序有没有人用

第二期（+2 天）：
  AI 助手 + Dashboard
  → 完善核心体验

第三期（+1 天）：
  合规检查 + Shopify 订单
  → 锦上添花
```
